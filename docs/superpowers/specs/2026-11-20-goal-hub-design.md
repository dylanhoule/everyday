# everyday: goal hub rework

Visual reference: `everyday-selection.pdf` (repo root). Page 1 is the desktop Today screen; pages 2-5 are phone screens (Today, Goals, Goal detail, Progress).

## Intent

everyday is a one-person PWA (React + Vite, deployed on Vercel, synced across phone and laptop). Today it is a flat todo list that used to be fed by a hand-seeded training plan; that plan was deleted because the user stopped using it and it went stale.

The rework turns it into a **goal hub**: the place where the user's goals live, and where each goal turns into the few things to do today to move toward it. The user writes and edits their own goals and habits in the app (not seeded from the repo, not generated by AI). The app's job is to make "what do I do today, and is it working?" obvious at a glance.

## Goals

- See every active goal and how it's going (countdown, on track / slipping, a progress measure).
- See today's "moves": every habit and task due today, check them off in one tap.
- Track amounts, not just checkmarks, where it matters ("6 of 15 mi this week").
- See consistency over time: day score, streak, 26-week heatmap, per-goal 14-day percentage.
- Create and edit goals, habits, path phases, and one-off tasks from the phone.

## Non-goals

- AI coach, AI-written notes, or automatic rescheduling. (Possible later; the data model below is what it would sit on.)
- A Coach tab. The mockup has no Coach screen; the only coach surface is one rule-based note card on Today.
- Multiple users or accounts. The shared-passphrase sync stays.
- Notifications or reminders.
- The Calendar view. It goes away; one-off tasks get a date field instead.
- A light theme. The design is dark; the current cream theme is retired.
- Importing old history. Scoring starts with the new app.

## Anti-goals

- Setup that feels heavier than the old todo list. Checking something off must stay one tap; adding a quick task must stay a few seconds.
- Losing or resurrecting data across devices. The existing per-record "newest edit wins" sync must keep working.
- Guilt UI. "Slipping" is information, not a scolding; no red banners, no streak-loss modals.

## Constraints

- Keep the stack: React 19, Vite, `motion`, `vite-plugin-pwa`, Vercel, Upstash Redis via `api/todos.js`, shared passphrase in `src/sync.js`. No new runtime dependencies unless something truly can't be done without one (fonts from Google Fonts are fine).
- Sync stays one JSON array under one Redis key, merged per record by `id` + `updatedAt` (`src/merge.js`). Deletes are tombstones (`deleted: true`), purged after 30 days.
- Dates are local calendar days built with `src/date.js` (`iso`, `today`), never `toISOString()`.
- No em dashes in UI copy, comments, or docs (user preference).
- Tests follow the repo convention: plain `node:assert` scripts run by `npm test`.

## Approaches

**Who writes the plan** (decided by the user):
- **A. The user, in the app** (picked). Forms for goals, habits, phases, tasks; the app derives each day. Rule-based coach note.
- B. Claude, in the repo, like the old seed-plan flow. Least UI, but no editing from the phone.
- C. In-app AI coach via the Claude API. Closest to the mockup's prose, but ongoing cost and much more build. It would need A's data model anyway, so it can come later.

**How it's stored** (builder's call, made by Claude, not objected to):
- **Typed records in the existing synced list** (picked). Goals, habits, tasks, and check-offs are all records in the one array, each with `id`, `type`, `updatedAt`. `merge.js` and `api/todos.js` work unchanged.
- Separate stores per type: more API code, same behavior, only pays off with many users.
- A real database (Postgres/Supabase): new service and auth for well under 1 MB of one person's data.

## Data model

Every record: `{ id, type, updatedAt, deleted? }`. Records with no `type` are legacy todos (see Migration).

**goal**
- `name`: short name for the sidebar and Today groups ("Half marathon").
- `title`: full statement ("Half marathon in under 2:00").
- `color`: one of a fixed palette of 6 (orange, blue, cyan, purple, green, pink).
- `date?`, `endDate?`: optional target date or range ("Race day Jan 1", "Dec 14 to 16"). Countdown counts to `date`.
- `note?`: one or two lines shown on the card when there is no current path phase ("Push, pull, legs, plus one upper day.").
- `measure?`: `{ unit, target, per: 'week' | 'total' }`, e.g. `{ unit: 'mi', target: 15, per: 'week' }`, `{ unit: 'sessions', target: 22, per: 'total' }`.
- `stat?`: `{ value, label }` free text for the third stat on the detail page ("9:09", "goal pace / mi").
- `path`: ordered phases, each `{ name, start, end, note?, target? }`. A phase's `target` overrides `measure.target` while that phase is current ("Build: 20 mi weeks").
- `createdAt` (date string), `archivedOn?` (date string). Archiving hides the goal and its habits stop being due from that date; past days keep counting them. Goals have no hard delete (claude's call: delete would silently rewrite past scores and streaks).

**habit** (recurring, belongs to a goal)
- `goalId`, `title`, `note?`, `time?` ("17:30"; absent = all day).
- `days`: weekdays it is due, 0-6 (fixed weekdays, not "any N per week", so "was it due today?" always has an answer).
- `amount?`, `unit?`: default amount logged per check-off ("3", "mi"). A habit with a unit but no amount logs `1` of it ("lifts"). A habit with no unit contributes to no measure ("Lights out by 11:30"). The editor pre-fills a new habit's unit with the goal measure's unit; the user can clear it. (claude's call)
- `startDate`, `endDate?`. A habit is due on a date only if it is within its own range, before its goal's `archivedOn`, and, for a dated goal, on or before the goal's last date (`endDate ?? date`).
- Removing a habit sets `endDate` to yesterday (it stops being due today, history stays); there is no hard delete. (claude's call)

**task** (one-off, dated)
- `goalId?` (none = "Other"), `title`, `note?`, `date`, `time?`, `amount?`, `unit?`, `done`, `doneDate?`.
- Tasks can be hard-deleted (tombstone); a deleted task leaves past scores. Fine, since a deleted task is usually a mistake.

**log** (one habit check-off)
- `id` is deterministic: `log:<habitId>:<date>`, so checking the same habit on two devices merges into one record.
- `habitId`, `date`, `amount`, `unit`. Amount and unit are copied from the habit at check-off, so editing the habit later doesn't relabel past logs. Unchecking tombstones it.

Amounts: habit logs and done tasks contribute `amount` (default 1) in their `unit` to their goal. A goal's measure sums contributions with `unit === measure.unit` (exact match; no unit never counts) over the current week (Mon-Sun) or all time.

**Grace period (user's decision):** a day stays open until the end of the next day. Yesterday's habits can still be checked off and count for yesterday; anything older is locked (logs for dates before yesterday can't be created or removed).

## Derived numbers

- **Due on a date:** habits due that weekday (per the range rules above) + tasks dated that day. A task only ever counts on its own date. (claude's call: no carry-forward into today's score, so a day's number never shifts at midnight.)
- **Done on a date:** a habit is done if its log for that date exists. A task is done for its date if it was finished by the end of the next day (`doneDate <= date + 1`); finishing it later clears it from Today but leaves its date a miss.
- **Day score:** done ÷ due, as a percent. A day with nothing due is a **rest day**.
- **Streak:** consecutive days with score >= 70%, skipping rest days. Open days (today and yesterday) never break it; they extend it once they reach 70%. Only locked days can break it. "N more to keep the streak" = `ceil(0.7 × due) − done` for today, when positive.
- **Best streak:** longest run, with its date range.
- **Goal %:** the goal's habit logs ÷ the goal's habit due-instances over the last 14 days (tasks excluded, since they're one-offs).
- **Status:** New while the goal is under 7 days old; otherwise On track at >= 80%, Slipping below.
- **History starts** at the earliest goal's `createdAt`. Earlier days render as empty (no data), not as misses.
- **Known ceiling:** past scores are computed from current habit schedules, so editing a habit's weekdays rewrites its past. Archiving or ending a habit (setting `endDate`) preserves history; editing days in place does not. Acceptable for one user; mark it with a `ponytail:` comment.

## Screens

Dark theme throughout, matching the mockup: near-black background, slightly lighter rounded cards, a display serif for big numbers and headlines (Newsreader from Google Fonts is a close match; builder may pick another close one), system/Inter sans for everything else. Goal color appears as a dot and in that goal's bars and dots. Update `theme-color` and the PWA manifest colors to the dark background.

Layout: phone below ~900px wide, desktop above.

**Phone: bottom tab bar** with Today, Goals, Progress (three tabs; Coach dropped).

**Desktop: left sidebar** with the wordmark, Today, Progress, a GOALS list (dot, name, and "43d" / "day 1" on the right; click opens goal detail), "+ New goal", and the user's initial and name at the bottom (hard-coded constant). The desktop Today page combines the goal cards grid, the Today list, and the heatmap, as on page 1.

**Today** (pdf p1 right column, p2)
- Date line, headline "<N> moves today." (desktop: "<Four> goals, <nine> moves today."; numbers as words up to twelve), and on desktop the fixed quote line from the mockup.
- Score block: a small vertical fill bar plus the big day score, "5 of 9 done", and the streak line.
- Phone groups items by goal with "<done> of <due>" per group; desktop shows one list with done items first, then open items, each ordered by time (all-day items after timed ones). Each item: checkbox, title, note (phone), goal dot + name (desktop), time or "all day".
- An **Earlier** group above today's items: yesterday's unchecked habits and tasks (checking them counts for yesterday), plus any older undone tasks (checking them just clears them; they stay a miss on their date). Hidden when empty. (claude's call: one group on Today rather than tappable week dots, since only yesterday is editable.)
- Checking an item logs its default amount in one tap. Tapping the row (not the checkbox) opens its sheet: note, logged amount (editable while the day is open), and Edit (habit editor or task sheet). Task sheets also have Delete; habit removal lives in the habit editor.
- A "+" on Today opens the task sheet (title, goal or Other, date defaulting to today, time, note, amount + unit).
- Coach note card (desktop under the list, phone at the bottom of the list): shown only when a goal is Slipping. Rule: pick the slipping goal with the lowest goal %, name its most-missed habit, e.g. "Finals is slipping. ENGL Project 3 missed 3 of the last 5 times it was due." Hidden otherwise.
- First run (no goals): an empty state pointing to "New goal".

**Goals list** (p3; desktop shows the same cards in a 2-column grid on Today, p1)
- Card: color dot + date label ("Race day Jan 1", "Dec 14 to 16", "Ongoing", "Started today"), status chip, title, headline number, segmented bar, one summary line, and on desktop the WHAT GETS YOU THERE rows.
- Headline: days to go if the goal has a future date; otherwise goal % (or "day N" while New).
- Bar: progress toward the measure (`sum ÷ target`) drawn as 5 equal segments; with no measure, the bar shows goal %.
- Summary line: current path phase name + "<sum> of <target> <unit> this week" (or "total") + next phase name if any; with no path, the goal `note`. Phone footer also shows "Today <done> of <due>".
- WHAT GETS YOU THERE rows: habit title, 7 dots for this week Mon-Sun (filled = done, dim = missed, ring = due later today or this week, faint = not due), and on the right "<done>/<due> this week", or the next due day ("Sun", "today") if none were due yet.

**Goal detail** (p4)
- Back link, ⋯ menu (Edit, Archive), goal name with dot, title, status chip.
- Three stats: days to go (or days in), goal %, and the free `stat` (omitted if unset).
- The path: vertical timeline of phases; current phase highlighted with "Now." plus measure progress; past phases muted.
- What gets you there: the habit rows, plus that goal's upcoming tasks, plus "Add habit" / "Add task".

**Goal editor** (not in the mockup; same visual language): full-screen sheet on phone, centered modal on desktop. Fields: name, title, color swatches, optional date / end date, note, measure (unit, target, per week / total), stat, path phases (add/remove/reorder rows: name, start, end, note, target), habits (title, note, weekday chips M T W T F S S, time or all day, amount + unit). Habit and task sheets reuse the same field components.

**Progress** (p5; desktop gets the same content in the main column)
- 7D / 30D / 90D toggle.
- Average day score for the range with "+N vs <previous range>"; bar per day with a dashed 70% line; rest days drawn as a dashed outline; today drawn as an outlined bar.
- Current streak and best streak (with dates).
- By goal: dot, name, a reason line, goal %. Reason: if Slipping, "<most-missed habit> slips most"; otherwise "<habit with most due-instances> <done> of <due>".
- Heatmap "Every day, all goals" (also on desktop Today): last 26 weeks, rows = weekdays, columns = weeks, 4 intensity steps by score, dashed outline for rest days, empty for no-data/future, outline on today. Caption "<n> of <m> days at 70%+ · last 26 weeks".

## Migration and cleanup

- Records with no `type` load as tasks: `title` = first line of `text`, `note` = the rest; keep `date`, `done`, `doneDate`. Migrate on read; the next push writes them back in the new shape.
- Keep tombstoning undone `plan-*` records on load and on every pull (`retireStale` with an empty keep set), because the synced store may still hold the deleted plan's tasks. Remove the call after a month.
- Delete `src/plan.js`, `src/plan.test.js`, `src/Calendar.jsx`, and the plan-seeding block in `App.jsx`. `TodoItem.jsx` and `swipe.js` go too unless the builder finds them worth reusing (delete moves into the item sheet; swipe-to-delete is dropped).
- `api/todos.js` and the Redis key stay as they are.
- Known ceiling: logs grow roughly 10 records a day, around 400 KB a year in the one blob. Fine for years; revisit (compact old logs into per-day totals) if it approaches Upstash's request size limit.
